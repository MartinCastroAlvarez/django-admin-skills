## REST: django-admin-rest-api

Base URL: `$DJANGO_ADMIN_URL/admin-api/api/v1/` — read the site origin from the `DJANGO_ADMIN_URL` environment variable.

Authentication is the Django session. Unsafe methods need the `csrftoken` cookie echoed in an `X-CSRFToken` header and a same-origin `Referer`:

```bash
JAR=$(mktemp)  # session cookies stay in a temp file, never in the repo
curl -s -c "$JAR" "$DJANGO_ADMIN_URL/admin/login/" -o /dev/null
CSRF=$(awk '$6=="csrftoken"{print $7}' "$JAR")
curl -s -b "$JAR" -c "$JAR" -X POST "$DJANGO_ADMIN_URL/admin-api/api/v1/login/" \
  -H "X-CSRFToken: $CSRF" -H "Referer: $DJANGO_ADMIN_URL/admin/" \
  -H 'Content-Type: application/json' \
  -d "{\"username\": \"$ADMIN_USER\", \"password\": \"$ADMIN_PASSWORD\"}"
```

| Operation | Needs | Method and path (relative to the base URL) |
| --- | --- | --- |
| What this account may do now | — | `GET registry/` |
| List / search / filter | view | `GET <app>/<model>/?q=&page=&page_size=&ordering=&<filter>=` |
| Retrieve one | view | `GET <app>/<model>/<pk>/` |
| History of one object | view | `GET <app>/<model>/<pk>/history/` |
| Autocomplete a relation | view | `GET <app>/<model>/autocomplete/?q=` |
| Add-form fields | add | `GET <app>/<model>/add/` |
| Create | add | `POST <app>/<model>/ body {"fields": {...}}` |
| Update (partial) | change | `PATCH <app>/<model>/<pk>/ body {"fields": {...}}` |
| Delete preview | delete | `GET <app>/<model>/<pk>/delete-preview/` |
| Delete | delete | `DELETE <app>/<model>/<pk>/` |
| Run an action | action | `POST <app>/<model>/actions/<name>/ body {"pks": [...]}` |

Errors come back as `{"error": {"code", "message"}}`; `validation_failed` adds per-field messages under `fields`. Fix the payload and retry once; `forbidden` and `not_found` are final.

## MCP: django-admin-mcp-api

Server `django-admin` at `$DJANGO_ADMIN_URL/mcp/` (JSON-RPC 2.0, same session and CSRF rules as REST). Every tool mirrors one REST endpoint and takes `app_label` and `model_name`; `pk` values are always strings.

| Operation | Tool | Extra arguments |
| --- | --- | --- |
| What this account may do now | `django-admin:admin.registry` | — |
| List / search / filter | `django-admin:admin.list` | `search`, `page`, `page_size`, `ordering`, any filter parameter |
| Retrieve one | `django-admin:admin.retrieve` | `pk` |
| History of one object | `django-admin:admin.history` | `pk` |
| Autocomplete a relation | `django-admin:admin.autocomplete` | `q` |
| Add-form fields | `django-admin:admin.add_form` | — |
| Create | `django-admin:admin.create` | `data` (field → value) |
| Update (partial) | `django-admin:admin.update` | `pk`, `data` |
| Delete preview | `django-admin:admin.delete_preview` | `pk` |
| Delete | `django-admin:admin.destroy` | `pk` |
| Run an action | `django-admin:admin.action` | `action_name`, `pks` |

A result with `isError: true` carries the upstream HTTP status: `403` and `404` are final, `400` lists the fields to fix.

## Workflow for a change

Copy this checklist and tick it off:

```
- [ ] Read references/<app>.<model>.md for the model
- [ ] Confirm the operation is listed as allowed
- [ ] Find the object(s): list with search/filters, then retrieve by pk
- [ ] Build the payload from editable fields only (choices: use the value column)
- [ ] Destructive or bulk? Show the delete preview / pk list and get a yes
- [ ] Send the call; on validation_failed fix the named fields and retry once
- [ ] Retrieve the object again and report the result
```
